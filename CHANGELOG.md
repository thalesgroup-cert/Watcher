# Changelog

## 4.0.0

### Upgrading from 3.7.x

This release changes the database, the API and the way the configuration file is versioned. Read this before pulling it.

1. **Back up first.** Copy your `.env` (and `deployment/.env`) somewhere outside the repository, and take a full dump of the MySQL database (`make backup` from `deployment/`).
2. **`.env` is no longer versioned.** The file that used to be committed is now `.env.example`. A plain `git pull` can refuse to run because of your local `.env`, and a `git stash` followed by `git stash pop` can delete it. Keep your backup, never copy `.env.example` over your `.env`, and add any variable you miss from `.env.example` by hand (every new variable has a default).
3. **Stop `watcher`, then migrate before starting the new image.** The container does not migrate by itself. Run `python manage.py migrate` once (`make migrate`), then start the application. The migrations are heavier than usual: new indexes on `dns_finder` alerts and on the timeline can take some time on a large database.
4. **Some data is lost on purpose.** Five migrations (`*_remove_subscriber_channel_flags`) drop the per-subscriber Slack, Citadel and TheHive choices: these channels are now switched on for the whole instance in **Connectors > Notifications**, and every notification type is **off until a superuser turns it on**. Reverse migrations restore the columns, not the values.
5. **Do not change `CONNECTORS_ENCRYPTION_KEY` during the upgrade.** Changing it makes the saved connector credentials unreadable. If you never set one, a key built into the code is used: set your own in a separate operation, and enter the credentials again.
6. **Check** the connectors, the scheduled jobs and the notifications once the application is up.

Rollback: restore the dump and go back to the 3.7.0 image.

### Breaking changes

- The interface is rewritten (Vite, TypeScript, React 19, MUI 9). Removed without replacement: the customisable dashboards and Wall Display, the layouts of the profile, and the 12 Bootswatch themes (a former theme that is no longer offered is cleared; `darkly` and `slate` are kept).
- Threats Watcher moves from `/` to `/threats_watcher`; the home page is the new Overview.
- API: the lists of `cyber_watch` and `threats_watcher` are paginated (`{count, next, previous, results}`, 100 per page); `posturls` and the `content` of data leak alerts are gone (`has_content` replaces the latter); anonymous visitors no longer see `ticket_id`, `comments`, `misp_event_uuid` and `last_event` of a legitimate domain; an unknown theme id answers 400.
- Watcher is served by Gunicorn with **one worker and 16 threads, on purpose** (the scheduler runs in the web process). Do not raise the number of workers.

### Added

- Monitored pages (Website monitoring > Pages): versions, diff, threshold, ignore patterns, screenshots.
- Keyword rules in Threats Watcher (all of / at least one of / none of), with the matched articles kept.
- Screenshots of monitored pages, data leaks and legitimate domains, taken by the isolated `screenshotter` service. It is built from the `screenshotter/` folder (no published image yet): it is in `deployment/` (own network shared with `watcher` only) and in the Helm chart, where it is off by default (`screenshotter.enabled`) and comes with a network policy that only lets Watcher in and keeps it away from private addresses.
- Screenshots: the capture of a long page is no longer taken for a screen-sized one. The thumbnail says when the page is longer than a screen (a fade and its size, e.g. "Long page - 1280 × 4559 px"), and the viewer has a "Fit the page" button (key 9) that shows the whole page at once. A capture that fails now says why instead of "the page may refuse robots": the site did not answer in time, the domain name could not be resolved, the certificate is not valid, the address is not a public one, and so on (the screenshot service answers with a reason; rebuild its image to get it, an older service gives the plain sentence).
- Domain expiry dates: the RDAP server of each extension now comes from the IANA bootstrap instead of a list kept in the code (more extensions get a date, and a domain the registry says does not exist is no longer sent to the WHOIS web service). The job of the legitimate domains no longer lowers a date on one answer: WHOIS never does, RDAP only when it gives the same earlier date on two passes less than a day apart; until then the stored date stays (new internal columns, migration `common.0008`). Its end line counts the sources and the answers held back. `python manage.py check_expiry_dates <domain>` compares the stored date with what the registries say now (read-only). Two new notifications, off until switched on in Connectors > Notifications (Slack, Citadel, email): a legitimate domain whose registry-confirmed date is within 30 days (once per date; migration `common.0010`), and a date the registry moved earlier twice in a row. A past date that no registry confirmed shows as Unconfirmed instead of Expired (migration `common.0009`). The third-party WHOIS web service (`whois-raynette.fr`, plain http) is gone: no domain name leaves Watcher for a service that is not its registry, `check_expiry_dates --both` is removed, and an extension without an RDAP server simply gets no date (the reason is shown). The registrar job of the sites (`update_domain_registrar_info`, every 30 minutes) is gone too: it looked every site up a third time and wrote its expiry date without any guard. The monitored sites follow the same guards for their domain expiry (migrations `site_monitoring.0039` and `0040`): the hourly RDAP job of the monitored sites is gone (the 15-minute job of Site Monitoring already covers every site, with the same lookup), an earlier date waits for a second RDAP answer, WHOIS never lowers a date, and the "RDAP data update" alert is raised once instead of on every pass for a domain whose registry gives no date. A past date nobody confirmed shows as Unconfirmed on the sites page too. Two new notifications, off until switched on in Connectors > Notifications: a monitored website whose domain, confirmed by the registry, expires within 30 days (once per date), and a monitored website whose domain goes from registered to not registered (the registry has to say so on two passes in a row; a domain that never was registered says nothing). The same detection feeds Pending actions (migration `common.0011`): a monitored website whose domain is now available (approving moves its legitimacy to the "available" level), and a legitimate domain the registry no longer knows (approving moves it to Website Monitoring and removes it from Legitimate Domains); when the domain is registered again before the approval, nothing is changed.
- Catalog of 17 notifications with editable messages, global search (Ctrl+K), activity feed, access log and a summary line per scheduled job.
- Overview (the home page): the week in one figure with its last 14 days, the latest AI summary, a card per module, the latest detections, the top vulnerabilities and the trending words. **Customise** chooses the blocks, on the account.
- Ctrl+K also opens a page or a tab, signs out, changes the theme and sets the effects.
- Themes Clay and Clay Light: glass panels over a backdrop with the eye of the Watcher logo (its iris follows the pointer, and a click makes it spring out), with three levels (Full, Calm, Off) set on the account.
- Pending actions: a cross to reject and a green button to approve (Approve and transfer, Acknowledge) on each line of the list.
- Connectors: the state of each one in five words with an icon (Working, Problem, To finish, Not tested, Not set up), and a board at the top that filters the list.
- Floating messages are solid and carry a bar that empties while they stay; it stops with the pointer over the message.
- Forms that were not clear now explain themselves: the alert levels of a monitored keyword (Warm under 3 articles, Hot from 3, Super hot from 10), the reliability of a source from High to Low and how a word's reliability is averaged, and "Notify when" of a monitored page (how much of the text has to be rewritten, added or removed, with usual values). Monitored keywords are listed with the latest added first.
- Profile > Appearance: the themes are in a Light and a Dark section, with filters (by mode or kind: standard, glass effects, high contrast, ambience), and a badge for what sets each one apart. New Display settings, kept on the account: row density (comfortable or compact), text size, reduced animations and colour-blind safe chart colours. A button puts the theme, the effects and the display back to the defaults.
- The profile page: your name, identifier and e-mail in a card at the top with **Change avatar** (the editor opens in a window) and **Change password**, and what your account may do (the former Access tab) under it. **My activity** shows what you created, modified and deleted today and over the last 7 days, and lets you pick the period (today, 7 or 30 days, all). The address `/profile?tab=access` opens the profile.
- Visitors (not signed in) now see every module: the ones that need an account are in the menu under **With an account**, as locked cards on the Overview, and each opens a page that says what the module does with a **Sign in to open it** button (you come back to it after signing in). Those pages call no API. The sign-in page only says **Watcher is reachable** (no figures) and lists the open and the locked modules.
- Cyber Watch is closed to visitors on the server except what the Overview shows: the figures and the five top CVEs. The full lists of CVEs, the ransomware victims and groups, and the watch rules matches (which reveal what the organisation watches) now ask for an account.
- Overview: the big figure now counts what concerns **your organisation** this week (data leaks, DNS threats, website changes and watch rule matches) instead of the news of the world; visitors, who have no organisation, still see the new CVEs and ransomware victims. The rows of the lists are real links (open in a new tab). The page is built from a single request, `/api/overview/`, instead of about twenty: each module still answers with the rights of the person, and Refresh reloads only that request.
- Overview, **Needs your attention** (signed-in people, can be hidden with Customise): what waits for a decision, one line per thing with how many and a link to get there, the worst first: subdomain takeover risks, expired domains, actions waiting for approval (opens their window), watch rule matches, data leaks, domains and SSL certificates about to expire, DNS threats and website changes to review. Lines at zero are left out.
- Threats Watcher, Trends: the words that **jump** come first. Each word says how it is doing in one word, **Hot**, **Rising**, **New**, **Steady** or **Fading** (the last 24 hours against a normal day, told in whole numbers: "normally less than 1 a day"), with a small chart of its week. The table keeps the word alone in its column, then Activity, Trend, Reliability and, on the right, First seen; a click on Activity sorts by the articles of the week. The API gives `mentions_24h`, `mentions_week`, `rising` and `daily` (articles of each of the last 7 days) and accepts `?ordering=-rising`; words with the same figure keep a fixed order from one page to the next.
- Threats Watcher, Trends: the word cloud is sized by what is talked about this week and coloured by heat (Hot, Rising, New, Steady, Fading, with a legend); a button gives back the most mentioned of all time.
- Threats Watcher, the window of a word: the top says one thing, how the word is doing, in a sentence; the reliability, the first sighting and the reason the word is in the list are kept quietly at the foot. The articles are listed by day with the **icon of their site** (kept by Watcher, which fetches it itself, for the sites of its own articles and sources only, never the browser), a readable title instead of the raw address, **Show the others** after the first six, and a **Read** mark on the ones this browser opened. A CVE opens in Cyber Watch.
- Cyber Watch, **CVE scores**: the CVSS score and the severity are now read wherever the source keeps them (CVE record, unified format, or a CVSS 3.x vector alone, from which the score is computed), instead of only one place where none was ever found: no CVE had a score, so the severity, "Critical - 7 days" and the order of "Top vulnerabilities" were empty or wrong. What the source leaves out on a later pass is no longer erased. A CVE is often published before it is scored: at each pass the job asks the source again for a few of the ones still without (their score, date and description), and `python manage.py enrich_cves` catches up the whole list at once. The source is a public service that limits its requests (HTTP 429): the pass then stops and the command waits as long as the source asks.
- Cyber Watch, **one match per object**: a rule that matched a CVE or a victim on several keywords gave one match per keyword (the same CVE twice, for "NetScaler" and for "Citrix"), which inflated "To review" and the Overview. There is now one match per rule and object, with all its keywords (shown as chips, "+2" beyond two), and one notification naming them. The existing matches are merged by a migration (`cyber_watch` 0003, reversible: it keeps the first keyword).
- Cyber Watch, **CVEs exploited in the wild** (CISA KEV): once a day Watcher reads the CISA catalogue of the vulnerabilities known to be exploited and flags the CVEs it holds, with the date they were added, the date to fix them by, and whether ransomware groups use them. The CVE table shows an **Exploited** chip (**Exploited - ransomware** when they do), has an **Exploitation** filter and an **Exploited in the wild** card, and the window of a CVE has an **Exploitation** section. On the Overview the exploited CVEs come first in the top vulnerabilities, and **Needs your attention** has a line for them. The catalogue is public and needs no key; it is a connector of its own, **CISA KEV** (address `CYBER_WATCH_KEV_URL`, empty: off), with its own Test button and health check.
- Cyber Watch, **EPSS** (FIRST.org): once a day Watcher reads the EPSS score of every CVE, the probability that it is exploited in the next 30 days, and shows it under the severity ("EPSS 94 %") and in the window of the CVE ("94 % chance of being exploited in the next 30 days, more likely than 99 % of the CVEs"). Sorting by `epss` and `exploited` works on the API (`?ordering=-exploited,-cvss_score`, several fields allowed). The service is public and needs no key; it is a connector of its own, **FIRST EPSS** (address `CYBER_WATCH_EPSS_API_URL`, empty: off). Both jobs run a few minutes after the start, then every morning, and appear on the Scheduled jobs page.
- Notification **CVE exploited in the wild**: when CISA adds a CVE that Watcher holds to its catalogue, a message goes out on Slack, Citadel, TheHive (a high severity alert) and by e-mail, with the CVE, its severity and score, its EPSS, the date to fix it by and whether ransomware groups use it. Only what CISA added in the last 14 days is news (a fresh install does not announce years of history), at most 20 per pass, and each CVE only once. Like every notification it is **off** until a superuser switches it on in Connectors > Notifications; the e-mail goes to the Cyber Watch subscribers who ticked **Exploited CVEs** (on by default).
- Cyber Watch, **CVEs and other advisories**: the source also sends advisories that are not CVEs (Rocky Linux, Debian, OSV, RustSec, malicious packages…), which were counted as CVEs. The figures (CVEs, Critical, the top of the Overview, the cards) now count the CVEs only; the CVE table has a **Type** filter (CVEs by default, **Other advisories** with their number, or both) and marks an advisory with an **Advisory** chip, without an NVD link. An advisory about a CVE ("DEBIAN-CVE-2026-1234") is now that CVE and not a second row: the ones already collected are merged by a migration (`cyber_watch` 0006), their matches following them.
- Cyber Watch, **filters of the ransomware victims**: the Group, Country and Sector menus offered the ten most active ones only; they now offer every group, country and sector that has victims (the busiest first: 67 groups instead of 10), and **Unknown** for the victims the source gives no country or no sector for, with their number. The charts of the Insights tab keep their short lists. The statistics also give the number of groups that have victims, apart from the number of groups the sources know.
- Website Monitoring, **fewer false alerts**: the first answer of the registry (RDAP) for a site is now its starting point and no longer an "RDAP data update" alert (a later change of registrar or date is still told); a "Server banner" alert needs a different product or major version (`nginx/1.28.3 (Ubuntu)` becoming `nginx/1.28.3`, or a patch of the same version, is stored without an alert); and the MX records are said to be gone only when two passes in a row find none, while a resolver that times out or does not answer says nothing about them (migration `site_monitoring` 0041, a counter on the site).
- Website Monitoring, **the RDAP pass no longer undoes the monitoring**: the lookup read every site at the start of a pass that lasts long, then saved the whole row, which put back the mail records, addresses, hash and banner the monitoring had written meanwhile and made them be reported again. It now saves only what it learned.
- Legitimate Domains, **domains the registry does not know**: a legitimate domain that the registry says does not exist is not ours (any more), whether it was registered before or never found. After two answers in a row it goes to **Pending actions** ("Domain lost"), where approving moves it to Website Monitoring and rejecting keeps it (a rejected one is not asked again). Until now only a domain seen registered before was queued, so the 366 domains added without ever being found were only noted. The page has a **Not registered** card, a filter and a red mark in the table and the panel. A name with a part before its registrable domain (`en.wordpress.com`) is never called lost: the registry only knows registrable domains, so it is marked "subdomain" (the same for the websites of Website Monitoring). The command `python manage.py queue_lost_domains` lists the domains found before this release and queues them with `--apply`.
- Pending actions, **deciding several at once**: each action has a tick box, with "Select all" and, once some are ticked, "Approve N" (named after what it does, such as "Move to monitoring N") and "Reject N", after a confirmation. One request (`POST /api/common/pending_actions/resolve/`, 500 at most): an action that fails or is no longer pending is reported and does not stop the others.
- Legitimate Domains, **certificates**: the SSL check (every 6 hours) now reads the certificate of the legitimate domains too, 12 at a time, and keeps its expiry date; until now only the websites of Website Monitoring were read, so the certificate column, filter and chart of the page were empty. A domain whose certificate cannot be read keeps its date.
- Legitimate Domains, **no date for an extension**: a domain whose extension has no RDAP server in the IANA list (about a quarter of the domains: `.de`, `.jp`, `.ru`, `.es`, `.cn`, `.io`, `.eu`…) now says "No expiry date available for this extension".
- Website Monitoring, **comments**: a website has a "Comments" field (300 characters), as a legitimate domain has: in the form to add (one website or several at once: the text is written on each) and to edit, as a small bubble next to the domain in the list, as a section of the panel, and searched by the search box. A lost domain moved from Legitimate Domains arrives with a dated line ("[2026-11-23] Moved from Legitimate Domains: not registered.") above the comment it had (migration `site_monitoring` 0042).
- **Comments written by Watcher itself**: when Watcher moves or changes a domain on its own it leaves a dated line at the top of its comments (`[2026-11-23] UDRP won (WIPO): moved from Website Monitoring.`): a lost domain moved to Website Monitoring, a UDRP win, an export from Website Monitoring or from DNS Threats to Legitimate Domains, a website marked "available", and a legitimacy raised by the registry lookup. The comments of the website now travel with it to Legitimate Domains (UDRP, export), and a UDRP win on a domain that already exists writes its line there too. A comment holds 300 characters and the text of a person is never cut: when the line does not fit it is not written (the history of the object keeps the event). The lookup writes on the comment the website has now, not on the copy it read at the start of a long pass.
- Connectors: the page shows twenty-five connectors per page instead of ten, so the fifteen or so of an instance are all on one page, with no page to turn; the pages appear beyond twenty-five. The CISA KEV and FIRST EPSS connectors have their logos like the others (the EPSS one, black, on a white plate so that it reads on a dark theme), and a test checks that every connector has its image, so that a new one cannot be forgotten.
- Import of a file in every form that adds several items at once (legitimate domains, monitored websites, DNS threats domains and keywords, Data Leak search patterns, monitored keywords, banned words, RSS sources): the same zone, where a file is dropped or chosen, reads a .txt (one domain per line) or a .csv (the column named domain, host, fqdn or url, otherwise the first one) in the browser, nothing is uploaded as a file. The list can be read and changed, then previewed or added. The most one import takes: 2,000 legitimate domains, 500 monitored websites, 200 DNS domains, 500 DNS keywords, 100 search patterns, 500 monitored keywords, 1,000 banned words, 200 RSS sources; a long list is said to make the periodic checks longer. Search patterns and feed URLs are read one line at a time, so that the commas of a regular expression or of an URL stay in them. A list of more than 200 items, typed or imported, is sent in batches of 200 with a progress bar, in any module that adds several at once; if a batch fails, what the earlier ones did is kept in the summary. A long summary lists the skipped items and the errors first.
- Adding several items at once can be cancelled and undone: a list that goes by batches has a Cancel button (it stops after the batch in progress and keeps what is done), and the summary of an import has **Undo this import**, which removes the items it created, asked twice.
- Connectors > **Scheduled jobs**: every scheduled job with when it last ran, how long it took (and the trend of its last passes), what it counted, whether it failed or overran its cycle, whether it runs now and when it runs next. The last 50 passes of each job are kept (new table `JobRun`, migration `common.0012`).

### Security

- E-mails escape what they display. The page downloads and the screenshot browser only reach public addresses, checked when the connection is opened (DNS rebinding), including WebSockets.
- Regular expressions of monitored pages that could freeze the server (a repeat inside a repeat) are refused.
- Screenshots and the global search are rate limited, and only a few captures run at the same time.
- Taking a screenshot of a legitimate domain requires the right to change legitimate domains.
